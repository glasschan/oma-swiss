# DOX framework

- DOX is highly performant AGENTS.md hierarchy installed here
- Agent must follow DOX instructions across any edits

## Core Contract

- AGENTS.md files are binding work contracts for their subtrees
- Work products, source materials, instructions, records, assets, and durable docs must stay understandable from the nearest applicable AGENTS.md plus every parent AGENTS.md above it

## Read Before Editing

1. Read the root AGENTS.md
2. Identify every file or folder you expect to touch
3. Walk from the repository root to each target path
4. Read every AGENTS.md found along each route
5. If a parent AGENTS.md lists a child AGENTS.md whose scope contains the path, read that child and continue from there
6. Use the nearest AGENTS.md as the local contract and parent docs for repo-wide rules
7. If docs conflict, the closer doc controls local work details, but no child doc may weaken DOX

Do not rely on memory. Re-read the applicable DOX chain in the current session before editing.

## Update After Editing

Every meaningful change requires a DOX pass before the task is done.

Update the closest owning AGENTS.md when a change affects:

- purpose, scope, ownership, or responsibilities
- durable structure, contracts, workflows, or operating rules
- required inputs, outputs, permissions, constraints, side effects, or artifacts
- user preferences about behavior, communication, process, organization, or quality
- AGENTS.md creation, deletion, move, rename, or index contents

Update parent docs when parent-level structure, ownership, workflow, or child index changes. Update child docs when parent changes alter local rules. Remove stale or contradictory text immediately. Small edits that do not change behavior or contracts may leave docs unchanged, but the DOX pass still must happen.

## Hierarchy

- Root AGENTS.md is the DOX rail: project-wide instructions, global preferences, durable workflow rules, and the top-level Child DOX Index
- Child AGENTS.md files own domain-specific instructions and their own Child DOX Index
- Each parent explains what its direct children cover and what stays owned by the parent
- The closer a doc is to the work, the more specific and practical it must be

## Child Doc Shape

- Create a child AGENTS.md when a folder becomes a durable boundary with its own purpose, rules, responsibilities, workflow, materials, or quality standards
- Work Guidance must reflect the current standards of the project or user instructions; if there are no specific standards or instructions yet, leave it empty
- Verification must reflect an existing check; if no verification framework exists yet, leave it empty and update it when one exists

Default section order:
- Purpose
- Ownership
- Local Contracts
- Work Guidance
- Verification
- Child DOX Index

## Style

- Keep docs concise, current, and operational
- Document stable contracts, not diary entries
- Put broad rules in parent docs and concrete details in child docs
- Prefer direct bullets with explicit names
- Do not duplicate rules across many files unless each scope needs a local version
- Delete stale notes instead of explaining history
- Trim obvious statements, repeated rules, misplaced detail, and warnings for risks that no longer exist

## Closeout

1. Re-check changed paths against the DOX chain
2. Update nearest owning docs and any affected parents or children
3. Refresh every affected Child DOX Index
4. Remove stale or contradictory text
5. Run existing verification when relevant
6. Report any docs intentionally left unchanged and why

## User Preferences

When the user requests a durable behavior change, record it here or in the relevant child AGENTS.md

## Local Contracts

- Plugin id `glasschan.oma-swiss`, kind `bar-widget`, single entry point `BarWidget.qml`.
- `BarWidget.qml` owns all state and actions; `ToolPanel.qml` is a pure view injected with `hostWidget` (consumes only the host members it names, via `t()` for strings). No state may live in the panel — the one sanctioned exception is view-transient UI state (the custom-ratio row's revealed/collapsed bit), never app state. The queued-eval slot lives in `EvalQueue.qml` — one module owning the single-slot queue, its eval runner and the completion notification; its interface is `enqueue(expr, notify, glyph)`. Panel sizing policy is host-owned too: the popup height has NO artificial cap — `contentHeight` is `fittedContentHeight(column.implicitHeight)`, so the shell's fit against `availableCardHeight` (real space on the anchor edge) is the ONLY ceiling (a fixed aesthetic cap left the column painting past the background — the 0.4.0 overflow). The column keeps `height: min(implicitHeight, panel.contentHeight - panel.verticalContentInset)` + `clip` purely as degenerate-screen containment (the ba30b4b class), and NOTHING in `contentHeight`'s dependency chain may read `column.height` — binding-loop discipline is a P0 class. Panel layout contract: header (quick-actions title + ↑ badge + language menu) → 快捷動作 → 視窗比例 → 切換 (toggles last); the four toggles (gaming, swap, looks, pin — in that order) are ONE group of single-line rows (icon + name + switch, ~36px) whose former card descriptions live in hover tooltips; the custom 寬/高/套用 row exists only while revealed — the 自訂… chip TOGGLES it (reveals, or collapses again, including an auto-revealed row), 關 or any preset collapses it, and EVERY panel open re-derives the reveal from the REMEMBERED last ratio (`onOpenedChanged` re-runs the derivation: last-aspect matching no preset → row revealed with the remembered prefill; a chip/preset click overrides until the next open — the loader never deactivates, so this MUST be an on-open re-derivation, not a one-shot initial binding; the 寬/高 field prefill rides the SAME on-open derivation — live custom ratio → last-aspect → 21:9 — and must never be one-shot `Component.onCompleted` work (that ran before hostWidget injection and left the fields on spinbox defaults forever — P2 fix, 2026-08-31)).
- Flag files are the source of truth and must stay byte-compatible:

  - Looks: `~/.local/state/omarchy/toggles/hypr/opinionated-looks.lua` — exists = Opinionated Looks on. Content is static-only `hl.config` (rounding/borders/shadow/blur; `lookLua` in BarWidget.qml carries the user's live tuning: border 5, rounding 6, gradient rim (bright top), blur size 6 / vibrancy 0.20 / vibrancy_darkness 0.1, shadow range 20 / power 4 / `rgba(00000028)` — re-tuned 2026-08-24). User-facing copy must never present the look as macOS-inspired or name macOS/Apple/Liquid Glass — macOS (27 Golden Gate as of 2026-08) is an internal research direction only (user rule 2026-08-24). A `setup-looknfeel.sh`-style marker block in `~/.config/hypr/looknfeel.lua` must not coexist with this flag: with the flag absent the block would keep the look applied and break the off state. The off path restores hard-coded Omarchy stock base values read empirically 2026-08-30 (misc:vrr is unset anywhere in Omarchy's config — Hyprland default 0; looknfeel.lua explicitly sets allow_tearing = false) inside the same flagEval expression; do not "simplify" the off path to a bare rm+reload, the hard-coded reset is the contract.

- UI language: `~/.local/state/glasschan.oma-swiss/lang`, one of `"en"` / `"zh"` / `"ja"` / `"ko"` (unknown or missing → en). All panel strings live in the `strings` table in BarWidget.qml and resolve through `tr()` — the panel stays a pure view; adding a string means adding it to every language block (all four blocks must keep full key parity — `checkStringParity()` warns at load time, and `tr()` falls back to en so a partial language can never render a raw key). IPC `lang` (no args) cycles en→zh→ja→ko→en. Registers: zh is 書面語 — standard written Chinese, never Cantonese colloquialisms (嘅／唔係／揀／成個…) — user rule since 2026-08-24; ja is standard polite です・ます体; ko is standard formal 합쇼체 (one register, no slang, never macOS). The header language control is a QQC2 Menu of self-named items (English／中文／日本語／한국어, checkmark on the active one) — like the tooltips it renders in the Qt overlay layer (the same popup mechanism), so it escapes the column's clip; it pops RIGHT-ALIGNED to the button (`popup(langButton, langButton.width - langMenu.width, langButton.height + Style.space(4))` — the panel anchors at the screen's top-right corner, so left-alignment runs the 160-wide menu off the panel edge; `langMenu.width` is explicitly set, hence stable pre-popup); selecting goes through the host's `setLang` via `root.tool`. System font fallback renders CJK + hangul — never bundle fonts or set `iconFont` on text strings. The bar-icon tooltip (`bar_tip_normal`/`bar_tip_swapped`) is two lines — line 1 exactly `OmaSwiss`, line 2 lists all three buttons (left tools · middle screenshot · right swap; the swapped variant's right action becomes restore), ≤ ~45 chars per line; the bar's tooltip Text renders `\n` natively (no wrap, no elide).
- Update indicator: `~/.local/state/glasschan.oma-swiss/update-check`, one line `<epoch-ms> <version>` (version optional — empty = last check failed; the parser must treat it that way — this format is byte-frozen). The panel-header ↑ badge (left of the language menu button, `Color.urgent`, click updates the plugin — git-managed installs run `omarchy plugin update --yes`; the shell hot-reloads plugin changes itself (debounced, watching the plugin dir), so no restart is issued — a forced `omarchy-restart-shell` during that reload raced the in-flight component creation and crashed the shell (issue #6); a failed update (dirty tree, network) fires one `upd_fail` notification, up-to-date clicks stay silent; non-git dev copies fall back to opening `releasesUrl`) shows while the GitHub latest release semver-exceeds the co-located manifest version. The only network touch is one `curl --max-time 5` fired from `open()` when the cache is older than 24 h — no timers, no polling, nothing while the panel is closed (resource floor intact); monitor instances share state through the file watch. `status` reports `update=<version>|none`.
- Release notes: `~/.local/state/glasschan.oma-swiss/update-notes` — written ONLY by the update check (same `updateProc` fetch): when the fetched version is newer than the manifest version, the release `body` is extracted with jq (guarded by `command -v jq`; jq missing/broken = write nothing) and truncated by jq to 8192 codepoints (`.[0:8192]` — never mid-UTF-8-sequence, which a byte cap alone would risk on multibyte CJK notes; `head -c 32768` remains only as a byte backstop that cannot engage on valid jq output), landed via mktemp-in-target-dir + `mv -f` (round-2 pattern). Every other outcome (fetch failed, not newer, jq unusable) `rm -f`es the file so stale notes never show; nothing in the notes logic can fail the version stamp (the JSON is echoed for the QML parser first, all notes branches exit 0). BarWidget exposes it as `updateNotes` via a watched FileView (unbounded read = accepted-risk policy); ToolPanel shows it as a hover tooltip on the ↑ badge (only while the badge is visible), `Text.PlainText` only (release notes are untrusted content — never rich text), wrapped at panel width and hard-capped at 16 lines — the elided tail lives on GitHub.
- Hotkey pin: `~/.local/state/omarchy/toggles/hypr/oma-swiss-hotkey.lua` — exists = pinned. Its static Lua does `hl.unbind("SUPER + CTRL + BACKSPACE")` + `o.bind(..., "omarchy-shell glasschan.oma-swiss aspectToggle")`; toggles load after user bindings, so the pinned bind wins while the file exists and removal restores whatever was bound before (stock or the user's own override). The write and the activating `hyprctl reload` MUST stay one shell command (FileView.setText is async — a separate reload Process would race).
- IPC surface (CLI = `omarchy-shell glasschan.oma-swiss <fn>`, exact function names, no hyphen mapping): `toggle` (swap), `aspect w h`, `aspectOff`, `aspectToggle`, `pin`, `look`, `gaming`, `lang` (cycles the UI language en→zh→ja→ko→en), `panel`, `open`, `close`, `status`. Quick actions have no IPC — they are panel buttons only (they close the panel on fire).
- Bar interactions: left-click opens the popup, right-click toggles the swap directly, middle-click fires the region screenshot quick action (stateless, never opens the panel; an open panel closes because the slurp overlay needs a clear screen).

## Work Guidance

- Resource floor is a hard design rule: no timers (except the 100 ms configreload debounce), no polling, no background services. File watching via FileView `watchChanges` only; hyprctl work through the single queued-eval slot in `EvalQueue.qml` so rapid clicks land in order. The swap/aspect flag writes/removals ride INSIDE the eval expressions (eval Lua carries io/os/math, verified 2026-08-24) — the atomic flag-mutation invariant is encoded once in `flagEval()` (BarWidget.qml); file and compositor state move as one and the old setText/rm race (flag file disagreeing with live state until a reload reasserted the stale side) cannot recur; a rejected eval writes nothing.
- Security hardening round 1 (marketplace baseline findings, 2026-08-24): every QML-derived path that reaches a `sh -c` command MUST go through `shellQuote()` — never raw single-quote concatenation (a quote-bearing HOME must not change the command). Every compositor/dbus subprocess carries a deadline — `timeout` in Process argv AND inside `sh -c` strings (quickshell ignores `running=true` on a busy Process, so an unbounded one silently swallows later toggles); the update check takes an `flock` on the state directory's inode (never a predictable lock file — see the follow-up bullet) so concurrent monitor instances never duplicate a fetch. The release job executes no network-fetched code (the unpinned upstream validator lives only in unprivileged CI, where the moving pin is intentional) and both workflows pin `actions/checkout` by full SHA.
- Security hardening round 2 (maintainer review of `331a883`, 2026-08-27 — write-side classes; briefly reverted by fc097db, restored 2026-08-29): flag writes must be symlink-safe atomic replacements — shell writes go `mktemp` in the target directory + `mv -f` (rename replaces a planted link; `writePinProc`/`writeLookProc`), eval-Lua writes go unique-temp-name + `os.rename` (`io.open "wx"` does not exist in hyprctl's Lua — verified 2026-08-27; `flagEval`); `FileView.setText` with `atomicWrites` (default) is already temp+rename and stays the write path for lang/last-aspect/update-cache. The release-check response is size-bounded both ways: `curl --max-filesize 262144` + `| head -c 262144`. Security hardening follow-up (marketplace review of `209f221`, 2026-08-27): the update check must NEVER open a predictable lock file — an `exec N>` open truncates through a planted symlink; mutual exclusion rides `flock` on the state directory's own inode (`exec 9<"${1%/*}"`, read-only fd, nothing created or truncated), and the legacy `update-check.lock` is unlinked in the same command (`rm -f` never follows a symlink); `check-hardening.sh` fails on any `exec N>` fd-redirection open.
- FileView content reads are a documented accepted risk (policy settled 2026-08-29 when fc097db removed BoundedFile.qml): FileView has no size/FIFO bound API, and every read target is a user-writable state file — the plugin's own `~/.local/state/glasschan.oma-swiss/` files AND the three watched flag files in Omarchy's shared `~/.local/state/omarchy/toggles/hypr/` (same risk class); a same-user writer there already owns the session, so unbounded reads are tolerated. Do not add polling to "fix" it, and do NOT plant FIFOs at watched paths in E2E — FileView may block on them by design.
- Quick actions and the update click are the two sanctioned exceptions to the queued-eval rule: stateless one-shot launches. They MUST go through `launchDetached` (`setsid -f ... </dev/null >/dev/null 2>&1`): quickshell Process children inherit piped stdio, and tools that read stdin block forever — slurp reads preselections from stdin before mapping its overlay, which was the OCR hang that stacked every later capture tool behind a dead grab. Detached also means no tool is ever killed by an actionProc restart or a shell restart. Because the detached update run swallows its own output, `handleUpdateClick` surfaces a failed update via one `omarchy-notification-send` (success and up-to-date stay silent). The panel closes when an action fires (selection overlays need a clear screen). The record and webcam actions choose start vs stop with a click-time `pgrep -f '^gpu-screen-recorder'` — a single check, never a loop. Both stop arms run `omarchy-capture-screenrecording --stop-recording` (the binary that owns the recording flag — the webcam wrapper parses no arguments, so a passed `--stop-recording` is silently dropped, and it exits outright with no webcam connected or a cancelled device menu; reviewer finding, 2026-08-30); the start arms differ (plain vs webcam wrapper). The two buttons share the recorder process namespace, so either stops a recording of either kind (accepted 2026-08-30). The bar icon's middle-click reuses the region quick action through the same launchDetached path.
- All plugin icons (bar + panel) are Tabler Icons (MIT, https://tabler.io/icons) rendered from the bundled `tabler-icons.ttf` — a ~6 KB subset, 14 codepoints (upstream webfont is 2.8 MB) loaded once via FontLoader; controls must set `fontFamily` to `iconFont`, because Tabler codepoints collide with Nerd Fonts' codicons range. Adding/changing an icon: look up the codepoint in @tabler/icons-webfont's `tabler-icons.css`, add it to the subset command documented in BarWidget.qml, rebuild with `fontTools.subset` FROM THE UPSTREAM WEBFONT (the bundled file already lacks any glyph not in its subset), and redeploy the font. The language button and its menu are plain text (system font fallback) and notification glyphs stay Nerd Font — the notification daemon renders with system fonts and cannot see the plugin's FontLoader. Custom SVG bar icons were tried and rejected (optical misalignment vs. font glyphs); keep the bar icon a font glyph.
- FileView caches content — a later `setText()` of byte-identical content silently no-ops. Any `rm` of a watched path that a later `setText()` targets must call `reload()` in the Process `onExited`; the current `setText` sites (lang, last-aspect, update-cache) are never preceded by an rm.
- hyprctl eval prints errors on stdout and exits non-zero on Lua errors; check both streams.
- The popup panel loads lazily (`Loader.active: false` until first open); keep it that way.
- CI (`.github/workflows/ci.yml`): `validate` runs Omarchy's own `omarchy-plugin-validate`, fetched fresh from `basecamp/omarchy` branch `quattro` (`bin/omarchy-plugin-validate`) — the moving pin is intentional, so Omarchy manifest-schema drift fails CI instead of silently accepting a manifest the shell would reject. It also runs `scripts/check-submission.sh` (marketplace SUBMISSION.md rules: README install+removal+deps, LICENSE, preview ≤50 MB/40 MP) and `scripts/check-hardening.sh` (line-based tripwires for the security-baseline classes that arrived as marketplace comments on 2026-08-24 and 2026-08-27 — paths into `sh -c` must go through `shellQuote()`, hyprctl in a Process argv must sit behind coreutils `timeout`, `curl` must carry `--max-time` AND `--max-filesize`, `omarchy-notification-send` needs a deadline, no `cat >` redirection writes (mktemp + atomic mv instead), dd reads need timeout + `iflag=nonblock` + byte caps, Lua `io.open` writes need `os.rename` on the same or next line, no `exec N>` fd-redirection opens, ToolPanel must call the host only through `root.tool` — plus the 書面語 rule for shipped Chinese; FileView content reads are the accepted-risk policy in Work Guidance and are intentionally not scanned; AGENTS.md itself is not scanned because the rule text quotes the markers). Release (`.github/workflows/release.yml`, on tag `v*`): tag must equal `manifest.json` `version`, then packages the plugin payload zip + sha256 and publishes the GitHub Release.
- Preview assets: `preview.png` is the 73:35 (2190×1050) marketing cover rendered from `design/cover.html` (Swiss style, red accent; embeds `../panel.png` on the right). The cover body font is Albert Sans — install the variable TTF (google/fonts `ofl/albertsans/AlbertSans[wght].ttf`) into `~/.local/share/fonts/` + `fc-cache -f` before re-rendering, or the cover silently falls back to Noto Sans (2026-08-31). `panel.png` is the raw popup capture, produced by diffing a matched screenshot pair (panel closed/open) — a plain trim bbox on the diff fails (bar clock/cursor/wallpaper noise inflates it); use connected components, keep blobs with bbox ≥25% of the largest, mask the top 26 px bar rows, crop with a ~14 px margin starting below y=26 — and it must show the EN panel (2026-08-31). When the two frames are far apart in time, desktop window content can produce diff blobs LARGER than the panel outside the panel region — run the CC analysis scoped to the panel's top-right anchor neighborhood and confirm the only blobs there are the card. The full validated pipeline (commands included) lives in skill `oma-swiss-preview` (`~/.agents/skills/oma-swiss-preview/SKILL.md`); re-render the cover with headless Chromium from `design/cover.html` and sync both PNGs to the deployed copy (static assets — no shell restart).
